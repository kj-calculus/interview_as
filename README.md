# 면접온 — 면접 방과후 관리

Vercel 배포: GitHub 저장소를 Import하고 Framework Preset은 Other, Root Directory는 기본값으로 둡니다. `vercel.json`이 빌드 명령과 출력 폴더를 지정합니다. 별도의 환경 변수 없이 배포할 수 있습니다. Vercel은 화면과 API 게이트웨이를 제공하고 기존 Sites API/D1에 연결하므로 계정·일정은 유지됩니다. 기존 Sites 사이트를 삭제하거나 비공개로 바꾸면 Vercel에서도 로그인·저장이 동작하지 않습니다. 새 주소에서는 다시 로그인해야 합니다. 검증: `node vercel/test.mjs`.

계정 관리에서 교사·학생 목록을 분리해 볼 수 있습니다. 관리자는 교사의 배정반을 `1반, 2반`처럼 쉼표로 여러 개 지정하거나 수정할 수 있습니다. 같은 반을 배정받은 교사는 해당 반 학생·일정·과제를 같은 권한으로 공동 관리합니다. 교사 화면의 반 탭은 선택한 반의 학생과 일정만 표시합니다. 기존 단일 배정반도 그대로 사용할 수 있습니다.

계정삭제는 관리자만 가능하며 확인 창을 거칩니다. 학생 삭제 시 개인 대학 일정과 로그인 세션도 삭제합니다. 교사 삭제 시 로그인 세션만 함께 삭제하며 반의 학생·방과후 수업·과제는 유지합니다. 배정반 변경 권한은 관리자에게만 있습니다.

Node.js 24 이상에서 `npm install` 후 `npm start`로 실행합니다. 접속: http://127.0.0.1:4173

관리자·교사·학생 로그인, 반별 달력, 학생별 대학 일정 흐름, 대학 일정 및 방과후 수업·과제 등록/수정/삭제, ExcelJS 기반 XLSX 양식 다운로드와 계정 일괄 등록을 제공합니다. 실제 운영 데이터를 입력하도록 예시 계정과 일정은 제거했습니다.

최초 실행 시 관리자 `admin` / `admin123`을 생성합니다. 서버는 비밀번호를 salt가 포함된 scrypt 해시로 저장합니다. 최초 비밀번호는 `ADMIN_INITIAL_PASSWORD`로 지정할 수도 있으며, 기존 데이터베이스의 관리자 비밀번호를 재시작으로 덮어쓰지 않습니다. 로그인 후 상단에서 비밀번호를 변경할 수 있습니다.

교사·학생 계정 등록 시 초기 비밀번호 777777이 발급됩니다. 비밀번호 초기화 시에도 777777로 설정됩니다. 발급 완료 창에서 계정 발급 내역 엑셀을 저장하고 사용자에게 전달합니다. 첫 로그인 시 비밀번호 변경이 필수입니다. 관리자 또는 해당 반 교사가 계정 관리에서 학생 임시 비밀번호를 재발급할 수 있습니다. 교사 계정 재발급은 관리자만 가능합니다. 재발급하면 기존 로그인 세션이 만료됩니다.

엑셀 열은 학번 / 이름 / 권한 / 배정반 / 아이디 순서입니다. 관리자 양식 권한은 교사·학생 드롭다운, 교사 양식은 학생 및 본인 배정반으로 제한됩니다. 업로드 시 권한·반·아이디·학번 중복을 재검사하고 오류가 하나라도 있으면 전체 등록을 막습니다.

계정·일정·세션은 `data/interview.sqlite`에 저장합니다. 세션 쿠키는 HttpOnly/SameSite=Strict이며 유효 시간은 8시간입니다. 서버는 모든 API에 인증과 역할·반 권한을 적용합니다. 교사에게 다른 반의 학생·일정을 전송하지 않으며 학생은 본인 일정과 본인 반 방과후 수업만 조회합니다. 학생의 등록·수정 요청은 서버에서 차단합니다.

교사 또는 관리자가 대학 발표·면접 일정을 각각 등록합니다. 1차 발표가 없는 전형은 생략할 수 있습니다. 학생별 대학 일정표는 시간순으로 일정을 연결합니다.

로컬 실행은 `npm start`를 사용합니다. 온라인 버전은 Sites의 Cloudflare Worker와 D1 저장소를 사용하며 `npm run build`로 생성합니다. 온라인과 로컬 저장소는 독립적입니다. `cloud/worker.mjs`가 온라인 API이며 `db/schema.ts`와 `drizzle`에 데이터베이스 변경 이력을 관리합니다. 온라인 초기 관리자 비밀번호 해시는 Sites의 `ADMIN_INITIAL_HASH` 비밀 값으로만 설정합니다. 온라인 비밀번호는 Web Crypto PBKDF2-SHA256으로 저장하며 쿠키에 Secure 속성을 적용합니다. 서버 로그인 시도 횟수는 D1에서 제한합니다.

로컬 데이터 백업은 서버를 종료한 상태에서 `data` 폴더 전체를 복사합니다. SQLite 데이터와 발급 비밀번호 파일을 소스 저장소에 포함하지 마세요.

`npm test`로 실제 HTTP 로그인·권한·등록·수정·삭제·비밀번호 재발급·서버 재시작 후 보존과 XLSX 양식/화면 생성 로직을 검증합니다. 테스트는 임시 데이터베이스를 사용하며 실제 데이터는 수정하지 않습니다. 브라우저 시각 검증 및 지원 브라우저에서의 WebMCP 검증은 수행하지 않았습니다.

ExcelJS 4.4.0의 MIT 라이선스는 dist/exceljs.LICENSE에 포함합니다.

학생은 대학 일정 입력에서 최대 6개 지원 정보를 직접 저장합니다. 전형·학과별로 일정을 구분하며, 날짜 미정과 바로 면접 응시를 지원합니다. 1차 불합격 이후 일정은 모든 역할에서 비활성화되고 달력·면접 건수에서 제외됩니다. 기존 교사 등록 일정은 유지됩니다.

자료실은 교사·관리자만 작성하며 학생은 열람·다운로드만 가능합니다. 전체 공개 또는 배정반 내 학생을 지정할 수 있고, 파일 다운로드에도 동일한 공개 범위를 적용합니다. 작성 교사와 관리자가 글을 수정·삭제할 수 있습니다. 첨부파일은 R2(로컬에서는 data/files)에 저장하며 게시글당 최대 3개, 합계 2MB입니다. 다운로드에도 로그인이 필요합니다.
방과후 수업은 달력 날짜에서 등록하며 전체 또는 반 내 학생 복수 선택이 가능합니다. 수업 종류는 1차-OT, 2차-개별지도, 3차-모의면접이며 개별지도에는 최초 등록자의 이름을 표시합니다. 기존 수업은 전체 대상 상태로 유지됩니다.

학생은 대학 일정 입력 아래에서 월~금 불가 요일과 비고를 저장합니다. 담당 교사·관리자의 학생별 화면에 표시하고, 수업 대상 선택 시 해당 요일 학생에 선택 가능한 음영을 표시합니다. 새 방과후 수업 시간은 7교시·8교시·상시입니다. 기존 시각으로 등록한 수업은 기존 값을 보존하며 수정 시 교시를 선택할 수 있습니다.

교사 달력은 2차 개별지도 중 본인 등록 일정을 기본으로 표시합니다. 다른 담당 교사 일정 표시와 대학 일정 표시를 독립적으로 전환할 수 있습니다. 최초 등록 교사는 계정 ID로 보존하며 기존 일정은 저장된 이름과 반에서 유일하게 식별되는 교사를 연결합니다. 발표 일정 상세에서 학생·담당 교사·관리자가 미정/합격/불합격을 저장할 수 있고, 지원 정보 기반 일정은 같은 지원 행에 반영됩니다. 오래된 화면의 결과 또는 지원 정보 저장은 충돌을 안내합니다.

계정 삭제는 학생의 개인 대학·개인 수업·진도·조정 정보를 함께 정리합니다. 다인 수업은 삭제된 학생만 대상에서 제외하고 마지막 대상이 삭제되면 수업도 삭제합니다. 교사는 등록자로 식별되는 일정과 중요 일정이 삭제됩니다. 등록자를 기록하지 않은 오래된 일정은 임의로 다른 교사에게 귀속하지 않습니다.
중요 일정(수능·휴업일 등)은 모든 계정에 별도 색상으로 표시하며 교사/관리자가 등록하고 등록자/관리자가 수정·삭제합니다. 방과후 탭에서는 전체 배정반 또는 반별 학생의 차수별 등록 횟수와 모든 수업 날짜·교시를 조회합니다. 완료 체크는 제공하지 않으며 기존 완료 기록은 보존합니다.

학생은 지원 정보를 저장할 때 주요 대학을 하나 선택해야 합니다(지원 정보가 전부 빈 경우 제외). 교사 달력만 선택된 지원 행으로 제한하며, 학생·관리자 달력 및 학생별 대학 일정표는 전체를 유지합니다. 기존 미선택 데이터는 첫 지원 행을 임시 기준으로 사용하며 다음 저장 때 선택을 요구합니다. 지원 행이 없는 기존 수동 대학 일정은 처음 등록된 대학·학과를 기준으로 표시합니다.
